第 1 步

貼上 GitHub 專案網址

在「GitHub 專案網址」欄位輸入要產生測試的公開專案，支援以下格式：

  • https://github.com/owner/repo
  • owner/repo（簡寫）
  • https://github.com/owner/repo/tree/分支名稱（指定分支）

「程式語言」和「測試框架」預設會自動偵測，想指定時再從下拉選單選擇。不知道要測哪個專案？點「範例」裡的專案名稱就會自動填入。最後按右下角的 產生測試。

第 2 步

等待分析完成

按下按鈕後，表單下方會即時顯示每個步驟的進度：

  • 讀取專案資訊與檔案結構
  • 下載核心原始碼檔案
  • 判斷語言並選擇測試框架
  • AI 撰寫測試（會顯示已產生的字數）

一般專案約需一到兩分鐘，期間請不要關閉頁面。若網址錯誤或專案不存在，這裡會顯示紅色的錯誤訊息。

第 3 步

查看結果總覽

完成後，下方會出現結果區：

  • 專案資訊：分支、語言、測試框架與目前模式
  • 數據卡片：測試檔數、測試案例數、分析了幾個檔案、專案原有測試數
  • 專案摘要分頁：AI 對專案的說明與測試策略，以及安裝與執行測試的指令
第 4 步

取得測試程式碼

切換到「測試程式碼」分頁，每個測試檔都會標示：

  • 建議放在專案中的路徑，例如 tests/cart.test.ts
  • 測試的是哪個原始碼檔案、涵蓋了什麼
  • 複製：複製程式碼到剪貼簿
  • 下載：下載單一測試檔

想一次全部帶走，按右上角的 下載全部測試（.zip），解壓縮後直接放進專案即可。

第 5 步

檢查測試案例清單

「測試案例清單」分頁用表格列出每一個測試要驗證什麼，方便你或團隊審查涵蓋範圍。上方的按鈕可以依類型篩選：

單元邊界錯誤處理整合

最後的「分析範圍」分頁會列出哪些檔案被分析、哪些因為太多而略過，以及專案原本就有的測試檔。

第 6 步

在自己的專案執行測試

把測試檔放到建議的路徑後，執行「專案摘要」分頁中提供的指令，例如：

npm install -D vitest && npx vitest run

如果有測試失敗，可能是 AI 的假設需要調整，也可能是你找到了一個真正的 bug，建議逐一檢查。

產出的是可以直接執行的測試

不是空泛的範本，而是根據你的程式碼寫出具體輸入與預期輸出的測試。

  • 匯入路徑對應專案中實際的檔案位置
  • 斷言具體明確，涵蓋正常、邊界與錯誤情況
  • 沿用專案既有的測試框架與程式風格
  • 附上安裝依賴與執行測試的指令
// tests/cart.test.js — 由 YourValidationAI 產生
import { calculateTotal } from "../src/cart";

describe("calculateTotal", () => {
  it("加總所有商品的小計", () => {
    expect(calculateTotal([
      { price: 100, qty: 2 },
      { price: 50,  qty: 1 },
    ])).toBe(250);
  });

  it("空購物車回傳 0", () => {
    expect(calculateTotal([])).toBe(0);
  });

  it("數量為負數時拋出錯誤", () => {
    expect(() => calculateTotal([{ price: 10, qty: -1 }]))
      .toThrow();
  });
});

常見問題

可以分析私有專案嗎？

公開服務只讀取公開專案。若要分析私有專案，可以自行部署 YourValidationAI，並在伺服器設定具有讀取權限的 GITHUB_TOKEN。

大型專案會分析全部檔案嗎？

系統會依重要性挑選最多 40 個核心原始碼檔案（約 30 萬字元）交給 AI，並在結果中列出未納入分析的檔案。若想聚焦特定模組，可以輸入指向該分支的網址。

產生的測試一定正確嗎？

AI 產生的測試是很好的起點，但仍建議在執行前審查。若某個測試失敗，可能是測試假設有誤，也可能是你找到了一個真正的 bug。

什麼是「範本模式」？

當伺服器沒有設定 AI 金鑰時，系統會以靜態分析找出公開函式，產生可自行補完的測試骨架。設定 ANTHROPIC_API_KEY 後即可使用完整的 AI 模式。
